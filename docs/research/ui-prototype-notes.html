0. 原型文件与入口

两份零依赖单文件 HTML,双击即开,全部为内存 mock,不做持久化:

  • prototypes/chat-ui-prototype.html — Chat 界面 5 变体,入口 ?variant=a|b|c|d|e,底部浮条或 ←→ 切换
  • prototypes/frontend-pages-prototype.html — Chat 之外的页面,入口 ?page=login|workspace|sessions|settings;composer 可真交互(发送 / Steer / abort / 队列出队 / 模型与 thinking 切换);&menu=model|think|attach 可深链展开菜单

mock 场景统一为:「查 readiness NaN」— pytest 白名单放行运行中 + pip install 待审批 + follow-up 排队,一次性压满 MessageList / ToolCallCard / ApprovalDialog / Composer 四个组件。

1. Chat 界面 — 5 个变体 已选型:侧栏工作台

落地状态(2026-10-08 晚):15 张票全部完成;v1 前端采用 侧栏工作台形态(SessionList + ChatView 两栏,即 B 变体方向的落法);无归档态随票 09 落地;set_model + Provider 注册表随票 14 落地。缺口:自定义 Provider(OpenAI 兼容 + Base URL)的动态注册未做,实现点在 ai/provider.py。

变体形态一句话定位
A 终端流单列消息流最接近 Claude Code 的阅读顺序,工具卡片内联在流里
B 侧栏工作台侧栏 + 对话 + modal审批/详情用弹窗,信息密度和导航最均衡
C 时间线 + 检查器左时间线 + 右检查器节点可点选,右侧看单个工具调用的完整入参出参与指标
D 文档画布prose 为主对话像文档,适合长报告型产出
E Claude Code 终端仿 CC TUI纯 mono、⏺ / ⎿ 符号、数字键审批、esc 中断状态行 — 用户指定做的模仿向

可能的组合方向如「B 的壳 + E 的对话渲染」,定了之后写进 issue 并作为 M0 前端基准。

2. Chat 之外的页面(frontend-pages 原型)

Login — 品牌场景

  • 整屏固定深色(canvas 动画,不随主题):agent 网络脉冲 — 节点漂移、邻近连线、事件沿边流动,鼠标视差;右下 HUD 实时显示 NODES / LINK / EVT
  • 品牌区:● AGENT LOOP · ONLINE 徽章 + 渐变流光 wordmark + 打字机任务行(循环输入示例任务)
  • 登录卡:玻璃拟态(blur + 内描边);实现照旧 POST /api/auth/login → token 存 localStorage,WS 以 query param 携带
  • 无障碍:prefers-reduced-motion 时画静态一帧、不打字;离开页面停 RAF 与 interval

Workspace — composer 仿 claude.ai

  • 大圆角卡片 + 内嵌工具行:+ 附件菜单(上传 / 粘贴图片 / @ 路径引用)、模型选择(全量 MODELS,含自定义,provider 徽章 + Base URL,切换即 set_model)、思考档位(低/中/高/超高/最大 → effort,set_thinking_level)、麦克风占位、圆形发送键
  • 运行态:发送键变深色 ■ = abort;placeholder 提示 Steer;Enter = 插话,Shift+Enter 换行,Esc 收菜单
  • Follow-up 队列 chip:运行中排队的消息,本轮结束自动出队作为新 Turn 发送(原型里可看到出队 → thinking 块带指标 → 流式回复全过程)
  • Thinking 块显示 时长 · tokens(如 6s · 187),5 个 chat 变体同款;E 变体为 CC 式 ✻ 思考了 Ns · N tokens + 状态行实时计数

Sessions / Settings

  • Sessions:搜索 + 状态过滤(全部/运行中/空闲),↗ 打开、✕ 删除
  • Settings:模型管理(点行设默认、自定义行可移除)、thinking 分段、Tool Approval 开关与白名单 pattern(全局/本会话)、并发 Loop 上限、bash 超时

3. 已定的产品决策

① Settings 支持自定义添加模型 已定

模型 ID + Provider(Anthropic / OpenAI 兼容 + Base URL),并入 GET /api/models。偏离 spec「v1 只接 Anthropic」——落地需要 ai 层第二个 Provider 实现(Provider 抽象已就位,见 issue 03 完成记录)。

② 会话生命周期 v1 只有 存在/删除,无归档态 已定

列表状态只有 运行中/空闲;删除即真删 JSONL 文件。用户明确否掉归档概念。

落地状态:② 已随票 09 实现(删除即真删);① 的「切换」部分已随票 14 实现,"自定义 Provider 注册"仍是缺口(见第 1 节)。

4. 未定项

  • Steer vs Follow-up 的 UI 选择 open — 运行中发消息,Enter=Steer(插话)还是显式排队?原型暂按 Enter=Steer + 预置队列 chip 示意;用户暂定「先这样显示」。
  • 并发 Loop 上限的溢出行为 open — 满员时新 prompt 是排队还是拒绝,spec 未写死。
  • 审批挂起是否占用并发名额 open — M7 计数口径的设计细节。
  • Chat 变体精细化 open — v1 已落侧栏工作台;C 的检查器、E 的 CC 式渲染等元素是否吸收,按需增量演进,不推翻已交付结构。

5. 实现备注(落地时要看的点)

  • Thinking 指标:时长好办(timestamp 相减);token 若要「按思考块单独计」,ai 层需在流式时按 content block 边界近似计量 thinking_delta(字符数/4 级别的估算),否则退到 Turn 级 output 总量(usage 按 message 累计,Anthropic 不单独报 thinking)——CC 实际也是 Turn 级口径。spec 不用改:条目已有 usage,message_update 带 usage 快照即可。
  • 多用户内网:login/workspace 均按用户隔离(会话 / 记忆 / 工作区);composer 切模型走 WS set_model,切换即刻生效。
  • Tool Approval:ADR-0001 内置 before_tool_call 钩子;Settings 白名单按工具/会话两级;关掉开关即回 pi 行为。
