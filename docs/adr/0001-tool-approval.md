# 0001 - 内置工具审批（对 pi 的偏离）

pi 的工具以进程全权限运行，没有内置审批，靠扩展拦截 `tool_call` 事件或容器化兜底。Super Agent 部署在多用户内网服务器上，bash 等危险工具的误触与滥用成本远高于单机终端场景，因此把审批做成了**内置的 `before_tool_call` 钩子**（默认开启）：危险工具执行前推送 `approval_request` 事件到前端，用户确认后才放行；白名单可按工具/会话配置，关掉白名单即回到 pi 行为。

## Considered Options

- 与 pi 一致不做审批——被否：多用户共享一台服务器，单次误操作的爆炸半径不可接受
- 每用户 Docker 容器强隔离——被否（v1）：部署复杂度过高；作为 v2 方向，`workspace.py` 已留 isolation 接口

## Consequences

- 工具执行管道必须支持"异步等待前端确认"（approval 挂起、超时拒绝）
- 这是刻意偏离 pi 的第二处（第一处是多用户形态），未来任何"对齐 pi"的重构建议都不应移除它
